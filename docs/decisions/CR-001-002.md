## CR-001 — A* heuristic safety margin

| | |
|---|---|
| Contract text (§3) | `m_min` = min of m over [−g_max, g_max] × (1 − 1e−9) |
| Proposed text | … × (1 − 1e−3) |
| Implemented in | `core/src/route.ts` `minMultiplier()` (already, pending approval) |
| Why | `m_min` is found by dense sampling (20 001 points). Tobler's minimum is a kink at g = −0.05; sampling can miss it by ~1e−4 relative, so a 1e−9 margin could make the heuristic inadmissible and A* could return a non-optimal route. |
| Interface impact | None. No field, type or file changes. |
| Behavioural impact | Route results are identical (optimal cost under the model). Only the number of expanded nodes can grow slightly. |
| Backward compatibility | Full. Consumers see no difference. |
| Regression evidence | `core/test/heuristic.test.ts`: h(goal)=0 and h(u) ≤ c(u,v)+h(v) on every edge of the real ROI-A grid for distance, Minetti and Tobler (>1000 downhill edges with cost < length); h ≤ Dijkstra optimum from 40 starts. `core/test/route.test.ts`: A* cost = Dijkstra cost on 200 random grids × 4 modes. `core/test/parity.test.ts`: A* = independent SciPy oracle on 501 random + 16 real cases (rel < 1e−9). All pass (33/33 on `feat/data-core`). |
| Rollback | Change one constant; tests above would still have to pass. |

## CR-002 — bundle discovery and `terrain.json` integrity

| | |
|---|---|
| Contract text (§2) | Bundle path `web/public/data/<roi_id>/<dataset_version>/`; `manifest.json` hashes "every file above"; no discovery file |
| Proposed addition | `web/public/data/index.json` = `{ <roi_id>: { dataset_version, path, terrain_json_sha256 } }`. Clarify that `terrain.json` is not in `manifest.json` (it contains `dataset_version`, which is derived from the manifest) and that its sha256 is in `index.json`. Hashed JSON files are written as exact bytes (LF), and `.gitattributes` marks `web/public/data/**` and `core/test/golden/**` as `-text`. |
| Implemented in | `pipeline/t04_bundle.py`, `core/test/bundle.ts`, `.gitattributes` |
| Why | The UI needs to find the current version without hard-coding it; without a hash for `terrain.json`, the route-critical metadata (nx, ny, spacing, x0/y0) had no integrity check. |
| Interface impact | Additive: one new file, no change to existing files or fields. |
| Backward compatibility | Full. A v1.0.0 loader that ignores `index.json` still works if it knows the version. |
| Regression evidence | `core/test/bundle.ts` verifies every manifest hash, manifest → `dataset_version`, and `terrain.json` → `index.json`. It is used by `parity.test.ts` and `heuristic.test.ts`, which pass in **both** worktrees. It caught two real defects during integration: CRLF conversion on checkout (fixed by `.gitattributes`), and Windows `write_text` adding CRLF before hashing (fixed by `write_bytes`). |
| Rollback | Delete `index.json`; loaders fall back to a configured version. |
